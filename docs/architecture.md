# 运行方式与边界

## 启动过程

1. macOS 启动入口寻找标识为 `com.openai.codex` 的官方应用。已运行时仅激活它，不重启。
2. 验证应用签名、Apple 信任链、OpenAI Team ID `2DC432GLL2` 和目标标识。允许 Finder 扩展属性存在，但检查签名资源和封装内符号链接。
3. 使用已验证官方应用内的 Node 运行时启动本地辅助脚本。
4. 随机分配调试端口，以 `--remote-debugging-address=127.0.0.1` 启动官方应用。音效开启时，使用本次启动的自动播放策略。
5. 连接前核对监听地址、所属用户和所属应用进程；页面 WebSocket 必须对应本次端口的本机页面端点。
6. 仅选择 `app://-/index.html` 主窗口；跳过浮窗、分离窗口和其他网站。
7. 通过页面协议执行本地动画源码和合并后的显示配置，确认播放开始后关闭辅助连接并退出辅助进程。
8. 动画结束移除 Shadow DOM 覆盖层，清理动画事件和声音，恢复原焦点与被暂时占用的全局动画 API。短暂状态标记稍后删除。

辅助进程只读取页面目标地址和本项目的播放状态，不获取聊天正文。没有资源服务器、守护进程、后台壁纸或持续注入轮询。

## 本机调试端口

调试连接没有独立认证机制。虽然仅监听回环地址，**同机其他进程仍可能连接并控制页面**。辅助进程退出并不会关闭官方应用自己持有的端口。

结束调试状态的方法：完全退出官方应用，再从官方原图标正常启动。不能把“动画消失”当成端口已经关闭。

本项目不会使用 `--remote-allow-origins=*`，也不会绑定 `0.0.0.0`、关闭证书验证或修改系统防护。若无法核对端口归属就停止接入。

## 没有改变的内容

官方应用签名、资源包、账号、模型和 API 配置不由启动器修改。动画中的 ROOT、网络已开放、推理强度和并行数量只是文案，不授予实际权限。

启动器配置和生成文件均保存在本地。公开仓库仅包含通用默认值；个人配置被 Git 忽略，但合并后的配置会进入你自行构建的应用，分发前应自行检查。

## 故障处理

- 找不到官方应用：确认已安装标识为 `com.openai.codex` 的桌面版本。
- 签名或运行时校验失败：从官方渠道更新或重新安装官方应用；不要删除本项目校验来绕过。
- 没有动画：确认完全退出后从新启动器打开；已运行应用不会自动重播。
- 接入超时：官方版本可能改变了窗口结构或调试开关；退出后从官方原图标启动，原应用仍可使用。
- 修改不生效：重新构建并更新安装副本；只改仓库里的 JSON 不会改变旧 `.app`。
- 新名称安装冲突：不要覆盖同名其他应用；修改 `config/app.json` 的 `displayName` 后重新构建。

## 验证边界

配置测试、CDP客户端测试、macOS构建和本地WebKit播放测试分别验证不同部分。模拟宿主不具备官方页面的全部 CSP、路由和窗口机制，构建成功与播放器检查成功不能证明真实冷启动接入成功。

若要报告兼容性，请同时注明官方版本、macOS版本、从新入口冷启动是否成功、音效是否播放，以及跳过和退场后原页面是否正常。报告中不要附聊天内容、令牌或其他私人资料。
